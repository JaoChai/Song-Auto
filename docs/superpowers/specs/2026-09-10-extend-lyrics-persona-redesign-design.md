# Song-Auto — ต่อเพลง, แต่งเนื้อด้วย AI, ยกเครื่อง persona และเปลี่ยนหน้าตา

วันที่ 2026-09-10 · สถานะ: รอรีวิว

## 1. ที่มา

ตอนนี้เชื่อม kie.ai Suno API ไปแล้ว 3 เส้นทางจาก 17 เส้นทางที่มีในเอกสาร — `generate`,
`generate/record-info`, `generate/generate-persona` งานรอบนี้เพิ่มอีกสองเส้นทาง
(`generate/extend`, `lyrics` + `lyrics/record-info`) ปรับ persona ที่ส่งพารามิเตอร์ไม่ครบ
และเปลี่ยนจานสีกับที่ทางบนหน้าจอ เพราะการ์ดในคลังรับของเพิ่มไม่ไหวแล้ว

## 2. สภาพจริงของข้อมูล

อ่านจาก D1 ตัวจริงเมื่อ 2026-09-10:

| | |
|---|---|
| เพลงทั้งคลัง | 2 |
| `status = 'SUCCESS'` | 2 |
| `suno_id IS NULL` | 2 |
| `title = ''` | 1 |
| personas | 0 |
| ความยาว `tags` สูงสุด | 420 ตัวอักษร |

ข้อมูลชุดนี้เปลี่ยนลำดับความสำคัญของงานสองเรื่อง

**เรื่องที่หนึ่ง — สองฟีเจอร์ติดคอลัมน์เดียวกัน** `suno_id` เริ่มเก็บตอน migration 0003
เพลงทั้งสองเกิดก่อนหน้านั้น ผลคือ `SongCard.tsx:27` (`canPersona = success &&
Boolean(song.sunoId)`) เป็นเท็จทุกเพลง ปุ่ม persona ที่ commit ไปแล้วจึงยังไม่เคยปรากฏบนจอจริง
และ extend ก็ต้องใช้ `audioId` ซึ่งก็คือ `suno_id` ตัวเดียวกัน

**เรื่องที่สอง — คลังน้อยคือสถานะหลัก** grid ที่มีการ์ดเรียงเต็มจอเป็นภาพสมมติ
สถานะที่ผู้ใช้เห็นจริงคือ grid เกือบว่าง จึงต้องออกแบบสถานะนั้นก่อน

## 3. ขอบเขต

**ทำ**

1. ต่อเพลง — `POST /api/v1/generate/extend`
2. ให้ AI แต่งเนื้อเพลง — `POST /api/v1/lyrics` + `GET /api/v1/lyrics/record-info`
3. ปรับ persona ให้ส่งพารามิเตอร์ครบและกันเงื่อนไขที่ kie ระบุ
4. เปลี่ยนจานสี ตัวอักษร และที่ทางบนหน้าจอ
5. เติม `suno_id` ย้อนหลังให้เพลงเก่า (เท่าที่ทำได้)

**ไม่ทำรอบนี้**

- `wav/generate`, `vocal-removal`, `mp4/generate`, `midi/generate`, `mashup`,
  `replace-section`, `add-instrumental`, `upload-cover`, `style/generate`, `sounds`
- รับ callback จาก kie (ยังใช้วิธี poll ต่อไป)
- ลบ persona
- ปุ่มสลับโหมดมืด (ออกแบบ token ไว้ให้แล้ว แต่ยังไม่ต่อปุ่ม)

## 4. สมมติฐานที่ตั้งไว้เอง

ทั้งสี่ข้อนี้ยังไม่ได้รับคำยืนยันตรง ๆ แก้ได้ทุกข้อก่อนเริ่มเขียนโค้ด

| # | ประเด็น | ที่เลือก | เหตุผล |
|---|---------|---------|--------|
| 1 | เพลงเก่าที่เติม `suno_id` ไม่ได้ | ปุ่มขึ้นแบบกดไม่ได้ พร้อมข้อความบอกเหตุผล | ซ่อนปุ่มเงียบ ๆ คือพฤติกรรมที่ทำให้ฟีเจอร์หายไปโดยไม่มีใครรู้มาแล้วครั้งหนึ่ง |
| 2 | โหมดมืด | ยังไม่ทำปุ่มสลับ | ไม่ได้ขอ และ token เตรียมไว้แล้วทำทีหลังได้ |
| 3 | เพลงที่ต่อแล้ว | เป็นการ์ดใบใหม่แยกในคลัง มีป้ายบอกว่าต่อจากใบไหน | ง่ายกว่าการซ้อนกลุ่มมาก และคลังยังเล็ก |
| 4 | ขอบเขต | สามฟีเจอร์ตามที่สั่ง | YAGNI |

## 5. ฐานข้อมูล

### migration `0005_extend_lineage.sql`

```sql
ALTER TABLE songs ADD COLUMN parent_song_id TEXT;
ALTER TABLE songs ADD COLUMN continue_at REAL;
CREATE INDEX IF NOT EXISTS idx_songs_parent ON songs (parent_song_id);
```

- `parent_song_id` — id แถวของเพลงต้นทาง (`NULL` = เพลงที่สร้างขึ้นเอง ไม่ได้ต่อจากใคร)
- `continue_at` — วินาทีที่สั่งให้ต่อ เก็บไว้แสดงผลอย่างเดียว

ไม่ตั้งตารางให้งานแต่งเนื้อเพลง งานชนิดนั้นอายุสั้นและใช้แล้วทิ้ง

## 6. ฝั่ง worker

### 6.1 `src/worker/kie.ts`

เพิ่มสามฟังก์ชัน และแก้ของเดิมหนึ่งตัว ทุกตัวใช้สัญญาเดียวกับที่มีอยู่แล้ว —
คืนค่าเมื่อสำเร็จ โยน `Error` เมื่อพลาด แล้วให้ผู้เรียกเป็นคนตัดสินว่าจะตอบ HTTP อะไร

```ts
export interface ExtendInput {
  audioId: string;          // = songs.suno_id ของเพลงต้นทาง
  model: string;            // ต้องเท่ากับ model ของเพลงต้นทาง
  defaultParamFlag: boolean;
  continueAt?: number;      // บังคับเมื่อ defaultParamFlag = true
  prompt?: string;          // บังคับเมื่อ defaultParamFlag = true และไม่ใช่ instrumental
  style?: string;           // บังคับเมื่อ defaultParamFlag = true
  title?: string;           // บังคับเมื่อ defaultParamFlag = true
  negativeTags?: string;
  personaId?: string;
  personaModel?: string;
  instrumental?: boolean;
}
export function validateExtend(input: ExtendInput): string | null
export async function kieExtend(env: Env, input: ExtendInput): Promise<string>   // → taskId

export async function kieGenerateLyrics(env: Env, prompt: string): Promise<string>  // → taskId
export type LyricsPoll =
  | { kind: 'PENDING' }
  | { kind: 'SUCCESS'; variants: Array<{ title: string; text: string }> }
  | { kind: 'FAILED'; error: string }
  | { kind: 'TRANSIENT'; note: string };
export async function kiePollLyrics(env: Env, taskId: string): Promise<LyricsPoll>
```

`kieCreatePersona` รับฟิลด์เพิ่ม: `vocalStart`, `vocalEnd`, `style`

กติกาที่ `validateExtend` ต้องบังคับ (มาจากเอกสาร kie)

- `defaultParamFlag = true` → ต้องมี `continueAt`, `style`, `title` ครบ และต้องมี `prompt`
  เว้นแต่ `instrumental = true`
- `defaultParamFlag = false` → ใช้แค่ `audioId` กับ `model`
- `continueAt` ต้องมากกว่า 0 และน้อยกว่าความยาวเพลงต้นทาง
- ขีดจำกัดตัวอักษรใช้ชุดเดียวกับ `validateGenerate`
- `personaModel` ใช้ได้เฉพาะ V5 ขึ้นไป

กติกาของ persona ที่ต้องบังคับเพิ่ม

- `vocalEnd - vocalStart` ต้องอยู่ระหว่าง 10 ถึง 30 วินาที
- `vocalStart >= 0` และ `vocalEnd` ไม่เกินความยาวเพลง
- โมเดล `V3_5` ทำ persona ไม่ได้

### 6.2 เส้นทางใหม่

| Method | Path | ทำอะไร |
|--------|------|--------|
| `POST` | `/api/songs/:id/extend` | ต่อเพลงจากแถว `:id` |
| `POST` | `/api/lyrics` | เริ่มงานแต่งเนื้อ คืน `{ taskId }` |
| `GET` | `/api/lyrics/:taskId` | ถามสถานะ คืน `{ status, variants? }` |
| `POST` | `/api/songs/backfill-suno-id` | เติม `suno_id` ย้อนหลังให้แถวที่ยังว่าง |

ทุกเส้นทางอยู่หลัง `authMiddleware` เหมือนของเดิม

### 6.3 `extendSong` — `src/worker/routes.ts`

1. อ่านแถว `:id` — ไม่เจอ → 404
2. ไม่มี `suno_id` → 400 พร้อมข้อความไทยที่บอกว่าเพราะอะไรและทำอะไรได้บ้าง
3. `status !== 'SUCCESS'` → 400
4. ประกอบ `ExtendInput` โดย**เอา `model` จากแถวต้นทาง** ผู้ใช้ไม่ต้องเลือกและเลือกไม่ได้
5. `kieExtend` → `taskId`
6. เขียนแถว `PENDING` สองแถว (`variant` 1 กับ 2) เหมือน `createSong` ทุกประการ
   แต่เพิ่ม `parent_song_id = :id` และ `continue_at`
   - `title` ตั้งต้นจาก `title` ของต้นทาง ถ้าโหมด custom ไม่ได้ตั้งมาใหม่
7. ตอบ `201 { songs: [...] }`

**จุดสำคัญ:** extend คืน `taskId` ที่อ่านผลผ่าน `generate/record-info` เส้นเดียวกับ generate
ทุกประการ ดังนั้น `kiePollTask`, `GET /api/tasks/:id` และ `useSongs` ทำงานกับเพลงที่ต่อแล้ว
ได้ทันทีโดยไม่ต้องแก้อะไร — ไม่ต้องเขียนระบบ poll ชุดที่สอง

### 6.4 `src/worker/lyrics.ts` (ไฟล์ใหม่)

- `createLyrics` — อ่าน `prompt` ตัดช่องว่างหัวท้าย ว่าง → 400, ยาวเกิน 200 → 400,
  เรียก `kieGenerateLyrics`, คืน `{ taskId }` ไม่แตะ D1
- `getLyrics` — เรียก `kiePollLyrics` แล้วส่งต่อ

ฝั่งหน้าเว็บถามซ้ำทุก 3 วินาที และเลิกถามเมื่อครบ 90 วินาที แล้วขึ้นข้อความให้ลองใหม่
งานที่ค้างอยู่ฝั่ง kie ไม่ถูกยกเลิก แค่เราเลิกรอ — ถ้าปิดแท็บกลางคันงานก็หายไปเฉย ๆ
ซึ่งยอมรับได้เพราะยิงใหม่ได้ทันที

การแปลง error ของ kie เป็นข้อความไทย (code 400 มีหลายกรณีย่อย)

| กรณีจาก kie | ข้อความที่ผู้ใช้เห็น |
|---|---|
| มีชื่อศิลปินอยู่ในคำอธิบาย | "เอาชื่อศิลปินออกจากคำอธิบายก่อน แล้วบอกเป็นแนวเพลงหรืออารมณ์แทน" |
| ถูกกรองเนื้อหา | "คำอธิบายนี้ถูกระบบกรองไว้ ลองเขียนใหม่ให้ต่างจากเดิม" |
| แต่งจากคำอธิบายนี้ไม่ได้ | "คำอธิบายกว้างไป ลองบอกธีม อารมณ์ หรือเรื่องราวให้ชัดขึ้น" |
| `SENSITIVE_WORD_ERROR` | ใช้ข้อความเดียวกับกรณีถูกกรอง |

### 6.5 `src/worker/personas.ts`

1. **กันซ้ำ** — ก่อนยิง kie ให้ `SELECT 1 FROM personas WHERE song_id = ?` เจอ → 409
   พร้อมชื่อ persona เดิม
2. **กัน V3_5** — `song.model === 'V3_5'` → 400
3. **ส่งช่วงวิเคราะห์** — รับ `vocalStart` / `vocalEnd` ส่งต่อให้ kie
4. **ส่ง `style`** — รับเพิ่มจากฟอร์ม ไม่บังคับ
5. **แปลง 409 จาก kie** เป็นข้อความไทย เผื่อกรณีที่ฐานข้อมูลเราไม่ตรงกับของ kie

### 6.6 `backfillSunoId`

สำหรับทุกแถวที่ `suno_id IS NULL` และ `status = 'SUCCESS'`:

1. จัดกลุ่มตาม `task_id` เพื่อยิง `record-info` ครั้งเดียวต่อหนึ่ง task
2. `kiePollTask` → ถ้าได้ `tracks` ให้เอา `tracks[variant - 1].sunoId` เขียนกลับ
3. ตอบสรุปว่าเติมได้กี่แถว เติมไม่ได้กี่แถว พร้อมเหตุผลของแต่ละ task

เรียกครั้งเดียวแบบมือ ไม่ต้องมีปุ่มถาวรบนหน้าเว็บ **ผลของขั้นนี้กำหนดว่าสมมติฐานข้อ 1
จะถูกใช้จริงหรือไม่** และ **ต้องมี `KIE_API_KEY` ใน `.dev.vars` ถึงจะทดสอบในเครื่องได้**

### 7.1 ที่ทาง

ทิศทางการไหลอ่านจากซ้ายไปขวา ซ้ายคือสิ่งที่ป้อน ขวาคือสิ่งที่ได้กลับมา

```
┌──────────────────────────────────────────────────────┐
│  Song-Auto            [ ค้นหา ]                       │
├────────────────┬─────────────────────────────────────┤
│ ① สร้างเพลง     │ ② คลัง                              │
```

- ทั้งฟอร์มและแผงรายละเอียดยังคง mount อยู่ตลอด ค่าที่กรอกค้างไว้ไม่หาย (พฤติกรรมเดิม)

### 7.3 การ์ดเพลง — สามอย่างที่ต้องแก้จากข้อมูลจริง

1. เพลงไม่มีชื่อขึ้นข้อความไทย ไม่ใช่ `Untitled`
2. คำบรรยายยาวได้สองบรรทัดแล้วค่อยตัด (`-webkit-line-clamp: 2`) แทนที่จะบีบเป็นบรรทัดเดียว
   — ค่าจริงยาวถึง 420 ตัวอักษร ตัดบรรทัดเดียวแล้วไม่เหลือความหมาย
3. เพลงที่ต่อมาจากใบอื่นมีป้ายเล็ก ๆ บอก กดแล้วกระโดดไปเพลงต้นทาง

### 7.4 ขั้นตอนของแต่ละฟีเจอร์

**แต่งเนื้อเพลง** — ปุ่มข้างหัวข้อเนื้อเพลงในฟอร์มสร้าง → ช่องพิมพ์ธีม (จำกัด 200 ตัวอักษร
พร้อมตัวนับ) → ระหว่างรอแสดงสถานะกำลังแต่ง → ได้ผลเป็นรายการให้เลือก แต่ละใบมีชื่อกับ
เนื้อย่อ → เลือกหนึ่งใบ เทลงช่องเนื้อเพลง (ถ้าช่องชื่อเพลงยังว่าง เติมชื่อจากใบที่เลือกให้ด้วย)
→ แก้ต่อเองได้ตามปกติ

**ต่อเพลง** — ปุ่มบนแผงรายละเอียด → ค่าตั้งต้นคือ "ต่อโดยใช้ค่าเดิม" กดปุ่มเดียวจบ →
"ปรับเอง" กางช่อง prompt / style / title และให้เลือกจุดต่อบนคลื่นเสียง → ยิงแล้วได้การ์ด
`PENDING` สองใบในคลังทันที ระบบ poll เดิมทำงานต่อเอง

**persona** — ย้ายจาก popup ในการ์ดมาอยู่บนแผงรายละเอียด ลากเลือกช่วง 10–30 วินาที
บนคลื่นเสียงเดียวกับที่ใช้เลือกจุดต่อเพลง คำอธิบายยังเติมค่าเริ่มต้นจาก tags กับ style เหมือนเดิม
เพลงที่ทำ persona ไปแล้วปุ่มกดไม่ได้พร้อมบอกชื่อที่เคยตั้งไว้

### 8.2 ตัวอักษร

| บทบาท | ฟอนต์ | เหตุผล |
|-------|-------|--------|
| หัวเรื่อง ชื่อแอป ชื่อเพลง | Chakra Petch | มีทั้งไทยและละติน เหลี่ยมแบบเครื่องเสียง |
| เนื้อความ ช่องกรอก เนื้อเพลง | Anuphan | มีทั้งไทยและละติน ตัวแปรน้ำหนัก 100–700 อ่านง่ายที่ขนาดเล็ก |
| ตัวเลข รหัส ระยะเวลา | JetBrains Mono | ความกว้างเท่ากันทุกตัว |

**ปัญหาที่แก้:** ของเดิมโหลดแค่ Inter ซึ่งไม่มีสระและวรรณยุกต์ไทย ข้อความไทยทุกบรรทัดจึงตกไปใช้
ฟอนต์ระบบ (Thonburi บน macOS) ที่ความสูงตัวอักษรและน้ำหนักไม่เข้ากับ Inter

**กติกาสำหรับภาษาไทย**

- `line-height` ของเนื้อความไม่ต่ำกว่า 1.75 เพราะสระบนกับวรรณยุกต์ซ้อนกันสองชั้น
  ค่า 1.5 แบบที่ใช้กับภาษาอังกฤษทำให้วรรณยุกต์ชนบรรทัดบน
- ขนาดตัวอักษรพื้นฐาน 16px และไม่ใช้ต่ำกว่า 13px กับข้อความไทย
- ห้าม `text-align: justify` — ไทยไม่มีช่องว่างระหว่างคำ การยืดบรรทัดจะฉีกคำ

**ต้องเลือกด้วยตาก่อนลงมือ:** Chakra Petch เป็นแบบไม่มีหัว ซึ่งดูโมเดิร์นแต่อ่านต่อเนื่องนาน ๆ
ล้าตากว่าแบบมีหัว จึงจำกัดให้ใช้เฉพาะหัวเรื่องกับชื่อ ไม่ใช้กับเนื้อความ ก่อนเริ่มงานควรทำหน้า
เทียบฟอนต์โดยใช้ข้อความจริงจากแอปแล้วดูด้วยตา ไม่ตัดสินจากชื่อฟอนต์

### 8.3 ปรับ design system

`design-system/song-auto/MASTER.md` ต้องแก้ตามให้ตรง ไม่งั้นรอบหน้าจะขัดกันเอง

- จานสีทั้งตาราง
- Variance จาก 3/10 เป็น 6/10 — ค่าเดิมหมายถึงเรียบและอยู่กลางจอ ซึ่งขัดกับที่สั่งว่าให้สดใส
- Page Pattern ให้ตรงกับที่ทางจริง (ของเดิมเขียนว่า slide-over แต่โค้ดทำเป็น sidebar ถาวร)
